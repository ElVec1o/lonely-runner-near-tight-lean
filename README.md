# Lean 4 sources for the near-tight lonely runner papers and the six-speed classification

Pre-release draft of 25 November 2026 (private repository). Author: Vico Bonfioli. License: CC-BY-4.0 (`LICENSE.md`).
Not peer reviewed. No DOI yet.

## Status in one paragraph

This repository holds 1,353 Lean 4 modules (26 MB) that the three papers on near-tight sets of lonely runner speeds cite as "Lean", and the classification of six distinct positive integers with `ML <= 1/7` (`TheoremA_unconditional`). It is **not self-contained**: the import closure of `LRSpectrumFull.Sext6.Release` has 18,946 modules, of which 17,597 are in the public five-speed archive and 1,349 are here (plus 4 `Gen` modules that `Release` does not import). **No clean-checkout build of this repository has been run.** "Lean-verified" below means: the saved build logs of the author's development tree end with `Build completed successfully`, contain no `sorryAx` and print only the three standard axioms for the declarations listed; the shipped sources contain no `sorry`, `native_decide`, `axiom`, `unsafe`, `implemented_by`, `extern` or `opaque` outside comments (source scan, below). Comments in 11 files were edited for this release; the declarations are unchanged (below). No human has reviewed the proofs; fresh AI sessions have read the statements of most modules.

## Assembling the tree and verifying

Needs `elan`, Rust (std only, for the archive's `regen_data.sh`), the Mathlib cache for the pinned revision, and 24 GB of memory. Never run a bare `lake build` (one lean process of this project needs 4 to 10 GB and lake starts one per core; the lakefile has no default target).

```
git clone https://github.com/ElVec1o/lonely-runner-five-speed        # version 1.0.2
cd lonely-runner-five-speed/repro && bash regen_data.sh --full --install --steps build,v3,s4o,lines   # restore the omitted generated modules (minutes)
cd ../..
git clone <this repository> lonely-runner-near-tight-lean
bash lonely-runner-near-tight-lean/repro/overlay.sh lonely-runner-five-speed --check    # 0 clashes expected
bash lonely-runner-near-tight-lean/repro/overlay.sh lonely-runner-five-speed            # copy
cd lonely-runner-five-speed/lean
lake build LRSpectrumFull.Sext6.Gap.All          # the Gap library and its 28 audit modules (cheap check)
lake build LRSpectrumFull.Sext6.Release          # everything, prints every #print axioms (long)
for m in TwoDir Height Weight1Stmt Weight1; do lake build LRSpectrumFull.Sext6.Gen.$m; done
```

Then compare the printed axiom lines with `repro/expected_output/` (`bash repro/judge_axioms.sh <log>` prints PASS or FAIL).
Cost, from the author's development tree (not a clean checkout, inferred for a clean one): `Gap.All` about 7.3 ks of own-module compile time (about 2 h serial), peak about 9 GB; `Release` adds the five-speed closure (27 h 39 min wall with two lanes in the archive's own rebuild) and the `K313` and `LRC5` closures: estimate about 46 h, peak up to 16 GB for two modules of the five-speed development. The first two commands of the dependency assembly are the archive's own.

## Main results

Statements are in the papers. Labels: Lean = as defined in the first paragraph.

| result | Lean declaration (namespace `LRSpectrumFull.Sext6` unless stated) | module | label |
|---|---|---|---|
| Value of `ML([N]` with `r > N/2` replaced by `mr)`: `max(1/(N+1), m/(mr+beta))`, tight iff `m(N+1-r) <= beta` (paper A1, Theorem 1.1) | `Gap.theoremV`, `Gap.theoremV_tight_iff` | `Gap/Value.lean` | Lean (the gcd form of the criterion and the excess identity are by hand) |
| `g_13 <= 3/41`; failure of Kravitz's original spectrum conjecture at `N = 13, 19, 25, 31, 37, ...` (A1, Corollary 1.2) | `Gap.inst_13_12_3`, `Gap.corA_b`, `Gap.corA_c` | `Gap/Cor.lean` | Lean for the instances listed in `repro/MAP.md`; other table rows computed |
| One-entry bound `ML >= 1/N` for `N >= 14`, `r <= N/2`, `w > N` (A1, Theorem 1.4) | `Gap.OE_low_unconditional` | `Gap/FinalCore.lean` | Lean; sharpness at `N = 13` computed |
| Added speeds: `ML >= 1/N` when the window of `r` has enough pairwise coprime integers (B, Theorems 1.1, 1.2, 1.4) | `Gap.theoremS_unconditional`, `Gap.ML_ge_robust_lin8`, `Gap.theoremS_linear` | `Gap/FinalCore.lean`, `Gap/LinLFinal8.lean` | Lean |
| Kravitz's lemma with an explicit size; insertion theorem (A2, Theorems 1.1, 1.2) | `Gap.Kstar_E`, `Gap.kravitz_5_1`, `Gap.ins_E`, `Gap.ML_snoc_le_Hform` | `Gap/KStarMain.lean`, `Gap/KStarCorB.lean`, `Gap/InsLower.lean`, `Gap/InsUpper.lean` | Lean (the maximum over all peaks is by hand) |
| Six distinct positive integers with `ML <= 1/7` are `c * (1,...,6)` up to order | `TheoremA_unconditional` | `K313/Final.lean` | Lean, standard axioms only; depends on `LRC5` (five speeds, `Sext6/LRC5.lean`, from the five-speed archive) and on 16 prime certificates |

Central idea of `TheoremA_unconditional`: a speed above `21^5` allows a Dirichlet time at which all six speeds are within `1/21` of integers; the rounded vector is not parallel to `v`, and `LRC5` with a two-direction bound gives `ML > 1/7`; below the box `21^5 = 4,084,101` (`TheoremBox`), a counting argument that uses 16 "clean" primes, each certified by a kernel-checked computation, shows that a configuration other than `c * (1,...,6)` cannot have `ML <= 1/7`. The full declaration table is `repro/MAP.md`; the table from paper numbers to declarations is the status table of each paper.

## What is not in Lean

By hand or computed, as the papers say: the rate of `N_0(k)`; `N_0(2) = 21` as an equality (computed for `21 <= N <= 221`); the value form of the linear-count theorem; the conjecture T-X for two removed speeds with a common factor; all tables of the papers (programs in the paper repositories). Statements that are `Prop` hypotheses in Lean and are discharged elsewhere: `DusartPi` (some older forms; the `_unconditional` forms do not reach it, see the closure test in `expected_output/hyg_Axioms12.axioms.txt`), `HeightBound` (cited from Yi, Gill and Bu, not used by `TheoremA_unconditional`).

## What was left out, and why

* `Sext6/Gen/LRC7.lean` (27 `EightCert27` axioms, never built), `Sext6/Tower/*` (incomplete, experimental), `Sext6/K313/{Neg*,Toy*,T1,T2,P101_*,P53_lp,P313_lp_s15}` and `Sext6/pilot/*` (experiments not imported by `Final`), the aggregator `LRSpectrumFull.lean`.
* `Sext6/Gen/LRC6.lean` and its chain (83 further modules of the older development: `BarajasSerra*`, `EightPlan`, `Delta2*`, `Kravitz*` and others). The chain contains `sorry` in stubs that are superseded and not on the path of `LRC6_sext` (its axioms are the three standard ones in the saved output `gen_LRC6.out`), but a repository that says "no `sorry`" cannot ship them without a flag. They are not needed by the papers or by `Release`. Shipping them is a decision of the author.
* All saved build logs: only the `#print axioms` lines, the `reachable` lines of the closure test and the final `Build completed` line are shipped (`repro/expected_output/`), because the logs are large and carry no information beyond these lines. `SUMMARY.tsv` lists, per log, the counts. Failed or superseded logs (`af_gasym.out`, `axioms12.out`) are not shipped.

## Source scan and edited comments

`repro/SOURCE_SCAN.md` records the checks run on the shipped files. Eleven files had comments edited (working notes, private paths, a stale status line); after deleting comments and docstrings every edited file is identical to the original (script run at packaging time). The two docstring corrections of substance: `K313/Final.lean` (the assembly uses the box `21^5 = 4,084,101`; the box `41,912,890` is a separate consequence of `Discharge16`) and `T2Height.lean` (`LRC 5` is proved in this development, `ResidueDataSub P16` is discharged in `K313.Discharge16`). The generated modules carry a banner naming the block generator; the generators are in the paper repositories (`code/`).
The shipped files are not byte-identical to the files from which the development tree was built, and `MODULES.sha256` and `CHECKSUMS.sha256` carry the hashes of the shipped files.

## Known issues

1. No clean-checkout rebuild; the build logs are of the development tree, where most `Gap` modules were rebuilt on 25 November 2026 after a comment-only edit (axiom lists identical).
2. Four audit modules (`Gap/Axioms12`, `16`, `17`, `18`) contain a meta-level `partial def` used only for the reachability test of `DusartPi`.
3. `K313/Discharge16.lean` states in a docstring that a box `41,912,890` is obtained; this is true of `TheoremBox_P16_unconditional` and is not the box used by the final assembly.
4. Statement fidelity (do the Lean statements say what the papers say) was checked by fresh AI sessions reading the modules and instantiating hypotheses; not by a human. The proofs of some modules (`Q81S*`, `MultiLower`, `OneRArc`) were not read in that check.
